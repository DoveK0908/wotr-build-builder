# 开拓者：正义之怒 · 构筑规划器（网页版）

[rt-planner](https://rt-planner.pages.dev/) 式的《Pathfinder: Wrath of the Righteous》**中文**构筑规划器。

与网上流传的构筑资料不同，**本项目的全部数据都不是手抄的**：直接从本机安装的游戏本体解包提取——

- `blueprints.zip`：25 万个游戏蓝图（职业、变体、专长、法术、神话道途、种族、背景……），含逐级升级表与前置条件
- `StreamingAssets/Localization/zhCN.json`：11 万条**官方简体中文**名称与描述

因此规划器里的每一个专长名、每一段描述、每一条「前置要求」都是游戏原版数据；连「角色创建时能选哪些职业/种族/神话道途」也是读游戏自己的 `BlueprintRoot.Progression` 拿到的，不是手写清单。

## 功能

- **建置顺序**：界面按做一张角色卡的顺序排成 9 步 —— ① 职业 › ② 种族 › ③ 背景 › ④ 购点 › ⑤ 技能 › ⑥ 逐级 › ⑦ 神祇 › ⑧ 阵营 › ⑨ 总结。「逐级」把专长、法术、神话阶层，以及每个职业自己的子选择（先知诅咒 / 秘示域 / 启示 / 奥法契约…）放在同一页：左边逐级卡片、右边这一级的进度与职业特性，同一张卡片里还有「同一步：神话第 N 阶」——职业与神话是并行的两条线（角色等级 N 对应神话第 ceil(N/2) 阶）。每一步都能直接点回去改；每一步的角落都会标出还差什么（还没选种族、购点还剩 3 点、还有 6 项专长没选、2 处阵营冲突……），也能用底部的「上一步 / 下一步」按顺序走。专长/特性的前置条件在每次操作后立刻重判：槽位里标红、本级下方出「前置不满足」标签，总结页的未完成清单也会列出来。
- **牌匾步骤条（照游戏做的）**：顶部那一条按游戏的角色创建界面复刻 —— 每块牌匾下面显示这一步选了什么（职业显示「先知」、阵营显示「LN」、购点显示「购点 17」、专长显示「0 / 19」），没配的显示「＋」，当前步骤高亮并在下面挂一个小三角指针，最前面是「20 等级」计数牌匾，条尾是六属性 + 购点总数 + 已排等级。**神话道途是立绘卡列表**（游戏里那张 854×227 横卡，选中叠金色描边与箭头，没选的变灰）；**步骤是动态的**：选定职业后会长出该职业自己的牌匾（先知 → 先知诅咒 / 秘示域 / 启示 / 额外法术；法师 → 专精学派 / 奥法契约；操念使 → 元素专攻 / 注能 / 原力），跟游戏里一样插在「专长」之后；把神话阶层推进去之后，同样会长出**道途自己的牌匾**（天使 → 超凡飞升 / 神话能力 / 神话专长 / 强化天堂宝剑 / 强化天使光环；巫妖 → 骷髅战将；御衡者 → 逼迫凝视；金龙 → 精通金龙吐息），插在「神话」之后；要自己挑法术的道途还会再长出「法术:等级 1 / 2 / 3 / 4」这一组牌匾（照游戏那一条来）
- **界面（暗色一套）**：整体是暗紫金的单页应用；游戏素材只用在两处 —— 神话步骤左栏的 **13 张道途立绘横卡**（选中叠金色箭头、门槛未达变灰），以及 **991 个 64×64 内容图标**（法术 498/699、特性 1886/10675 能对上真实图标，对不上的回退成首字徽记，游戏自己对背景也是用字母缩写当图标的）。蓝图里的图标引用是 `m_Icon{guid, fileid}`，而安装里**没有** guid → sprite 的对照表（`Bundles/` 的包名、container、`dependencylist.json`、`cheatdata.json` 都查过了），只能按名字约定对位，细节与实测覆盖率见 [`docs/game-ui-spec.md`](docs/game-ui-spec.md) 第 7 节。（原本还有一套羊皮纸主题，2026-10-16 按用户要求去掉了，只留暗色。）素材是 `pipeline/extract_ui.py` 用 UnityPy 从本机安装里导出的
- **三栏版面（照游戏做的）**：每个步骤页都排成游戏那样的三栏 —— 左边是可搜索的**候选列表**（40×40 图标 + 名称 + 第二行说明 + 右侧数字/徽章，选中是紫色高亮，有下级的带 `»`），中间是**详情栏**（大号衬线标题 + 机制高亮 + 图标网格 + 参数选择），右边是**数值栏**（数值盒子与键值行：强韧/反射/意志 高低、基础攻击加值档位、生命骰、技能点、本职技能、逐级填写情况……）。选择本身还是选择表时会一层层往下展开，跟游戏一样
- **种族 / 背景 / 购点 / 神祇 / 阵营**：种族（含传承选择、人类/半精灵/半兽人的任选属性 +2）、背景（按游戏里的层级选：大类 → 具体背景 → 有些背景还要再选一项，例如自然学者要选一个德鲁伊戏法）、属性购点（标准 25 点表，并按「基础 / 种族 / 升级 / 特性 / 手工」拆开显示；**每项属性旁按本职职业打绿拇指/红拇指** —— 口径就是蓝图里的 `RecommendedAttributes` / `NotRecommendedAttributes`，27 个职业带这份名单，32 个变体在自己的覆盖标记打开时会改写它）、神祇、阵营（八瓣扇形轮盘）。**有意与游戏不同的一处**：游戏里神祇（以及阵营的某些选择）一旦确定就无法更改，这里允许随时改，方便对比不同信仰/阵营的构筑；改完职业与领域会按新阵营重新判定
- **职业（20 级）**：逐级选职业（27 基础 + 13 进阶），**点职业只定这一级、不自动跳级**；中间栏那块可展开/收起的成长表就是该职业完整的 20 级信息，**这个职业实际排到的等级会高亮**（点表头的等级号可切到那一级，`#tab=class&lv=7` 也能直接跳）；变体在左栏该职业本体下面展开（**一个职业同时只能有一个变体** —— 原作规则，游戏本体如此，同时叠两个要靠 MOD；点第二个会顶掉第一个，另有「不用变体」可清空）；奇数级的**通用专长**来自游戏的角色通用升级表；每一步的概览会累计 BAB / 三豁免 / 生命 / 技能点
- **专长与逐级选择**：每级要选的东西集中在专长一步（职业给的专长与能力、通用专长、神话阶层槽），参数化专长（武器专攻、法术专攻、超魔……）会额外要求你选参数；挑选取的列表里，**已经拿过的选项会打一个绿色叶子小标**（与游戏一致），避免重复选
- **选择里的选择**：很多选择项本身又是选择表（`战斗专长 › 战斗流派专长`、`额外专长 › 高等元素专攻`、`神话能力 › 巅峰元素`、`种族传承 › 基本 › 一技之长`……），界面会一层层往下展开；改写上层后，下层不再可达的旧选择会被丢掉，不会悄悄留在构筑里
- **前置校验**：每一条候选都会实时判定 `可用 / 前置不足 / 无法判定`，并把不满足的条件用中文写出来（属性、职业等级、前置专长、选择列表、神话阶层……）。游戏里 **30 种**前置组件全部导出，包括最容易漏的三类：神话阶层门槛（金龙/魔鬼/虫群行者要神话阶层 ≥ 7）、仅主角/仅同伴、剧情进度（后两类保留原文、不拦人）；`oneof` 里「需要 2 项及以上」的写法按数量判定；另有 **88 个选择表在游戏里本来就是「不检查前置」**（圣教军额外专长、战士额外专长、游荡者天赋……），界面照实标成「不检查前置」而不是误报前置不足
- **阵营限制**：阵营不是摆设 —— 职业蓝图自己就带门槛（圣武士只收守序善良，武僧/地狱骑士/地狱骑士持节士要守序，德鲁伊与化形师拒绝守序，野蛮人不能守序，刺客要邪恶），8 个变体另有自己的要求，33 个神祇各自限制你能选的阵营，善良/守序等领域也按阵营开门。规划器把这几处读全了：阵营下拉会把不允许的阵营标灰并写明原因，神祇下拉把与当前阵营不符的信仰标灰，职业下拉标注「阵营不符」并禁用，冲突时角色页与汇总页直接列出原因。变体自带阵营要求时会**取代**母职业的要求（游戏里唯一一例：武僧 × 醉拳大师，守序与「任意非守序」互斥，以变体为准，此时职业下拉会提示「需要 守序，或选醉拳大师则改为它的阵营要求」）。神祇页中间那张表也照游戏做了：**先决条件（N/M）** 逐条列出并于每条前面打勾——满足是绿勾、游戏内才判定得了的（剧情进度）是灰问号、不满足是红叉，阵营那一行还会写出「当前阵营」；「无变体：野性神卫（战斗祭司）」这类条目会带上变体名与母职业名
- **神话**：10 个神话等级。**前两阶没有道途** —— 第 1 阶选一项「超凡飞升」+ 一项神话能力、第 2 阶一项神话专长，走的都是通用的「神话英雄」升级表；六条主道途（天使/恶魔/御衡者/灵使/诡计大师/巫妖）从**第 3 阶**起生效，金龙/虫群行者/魔鬼/传奇这类晚期道途要到**第 8 阶**才换。神话能力/神话专长按奇数阶、偶数阶轮换。神话阶层本身不提升属性；道途特性带来的属性加值会自动计入属性面板（例如传奇的全属性 +4、恶魔的高等恶魔之相按阶层给一项属性）
- **道途法术书**：六条道途里有七张自己的法术书 —— 天使（感知）与巫妖（智力）会**并进**职业法术书，御衡者/灵使/恶魔/诡计大师/金龙是独立法术书（用魅力）。游戏里要自己挑法术的道途（灵使、御衡者、恶魔、诡计大师）会为每一环单独出一块「法术:等级 N」牌匾，这里同样做成动态步骤，直接跳到那本法术书的那一环；天使/巫妖整张表都会（`allSpellsKnown`），游戏里没有挑选步骤，这里也不出。**法术位按角色等级索引**（实测：灵使 6 级才有第 1 环，天使 1 级就有）、可选法术按道途给（天使 85 条、巫妖 131 条、御衡者 103 条、灵使 85 条、恶魔 63 条、诡计大师 59 条、金龙 38 条）
- **技能**：本职技能、逐级技能点、关键属性调整
- **法术**：每个施法职业的已知/每日法术位、按环位选择法术、领域/血统/庇护主额外送的法术
- **汇总（按游戏角色卡排）**：左栏＝角色牌 + 属性块（基础/种族/升级/特性/手工分开列）+ 攻击框 + 防御与豁免框；中栏＝角色卡 + **1–20 级成长表（每级给了什么特性）** + 种族与背景特性 / 特殊能力 / 专长 的图标网格 + 法术环位与已选法术 + 逐级升级记录 + 未选完清单；右栏＝技能两栏 + 武艺特性 + 分享与存档。最后一步的「下一项」会变成「完成」，点它复制分享链接
- **分享与存档**：分享链接（`#b=…`）、构筑代码（可粘贴回填）、JSON 导出/导入
- **预置构筑**：内置 24 套中文队友 BD（来源与解析说明见 [`docs/presets-source.md`](docs/presets-source.md)），一键载入后继续改

## 目录结构

```
.
├── archive/                 旧 Tkinter 构筑工具（独立归档，自带 git 仓库）
├── pipeline/                Python 数据管线
│   ├── build_data.py        游戏数据 → web/public/data/*.json（带硬校验）
│   ├── check_data.py        管线产物自检
│   ├── extract_ui.py        本机游戏的界面贴图与内容图标 → web/public/assets/（需要 UnityPy）
│   └── import_presets.py    中文 BD 合集 → web/public/data/presets.json
├── web/                     前端（Vite + React + TypeScript）
│   ├── public/data/         管线产物（构建时原样进 dist/data/）
│   ├── public/assets/ui/    16 张界面贴图（神话道途立绘卡、箭头、绿叶子、放大镜）
│   ├── public/assets/icons/ 891 个内容图标
│   ├── src/                 数据层（load/store/rules/steps/skin）+ 步骤界面
│   └── scripts/             冒烟测试与无头渲染检查
└── docs/                    数据格式、预置来源、游戏界面复刻说明
```

## 数据来源

默认读取本机 Steam 安装目录：

```
D:\SteamLibrary\steamapps\common\Pathfinder Second Adventure
```

可用环境变量 `WOTR_GAME_DIR` 或 `--game <目录>` 覆盖。管线只读游戏目录里的 `blueprints.zip` 与 `Localization/*.json`，不修改游戏本体。

## 部署（当网站跑）

双击仓库根目录的 `启动网页版.bat` 就行：它会在需要时装依赖、跑一次生产构建，再用内置的零依赖静态服务器把 `web\dist` 发布到

http://127.0.0.1:5200/

（批处理本身只用 ASCII 写，中文提示交给页面；加 `--no-open` 参数可以只起服务、不自动开浏览器。）

想手动来：

```powershell
cd web
node node_modules\vite\bin\vite.js build            # 产出 dist（约 19 MB，含数据与两张素材目录）
node scripts\serve.mjs --port 5200                  # 只监听本机
node scripts\serve.mjs --host 0.0.0.0 --port 5200   # 同一局域网里的手机 / 平板也能打开
```

构建产物里带着从本机游戏提取的界面贴图与图标（`dist\assets`，归 Owlcat），所以这个站点适合自己在本机 / 内网用。

## 传到公网（GitHub Pages / Cloudflare Pages / Vercel）

游戏贴图与图标是 Owlcat 的版权物、也没有入库，所以公网版**必须**用「不含素材」的构建：

```powershell
cd web
npm.cmd run build:public      # = tsc + vite build --mode public + scripts\strip-art.mjs
```

`.env.public` 里的 `VITE_ART=0` 会让界面不引用任何游戏素材（立绘卡换成文字行、绿叶子/放大镜换成正字符号、图标回退成首字徽记），`strip-art.mjs` 再把 vite 从 `public/` 整包拷进来的 `assets\ui`、`assets\icons` 删掉。产物约 **9.6 MB**（页面 + 规则数据），没有任何游戏素材。构建用相对路径，丢进子目录也能跑。

三个平台怎么填（都从仓库根开始）：

| 平台 | 设置 |
| --- | --- |
| **GitHub Pages** | 已经写好 `.github/workflows/pages.yml`：推送后在仓库 Settings → Pages → Source 选 **GitHub Actions** 即可；CI 会自动 `npm ci` + `npm run build:public` + 冒烟自检后发布 `web/dist`。地址形如 https://<用户名>.github.io/<仓库名>/ |
| **Cloudflare Pages** | 连仓库，Root directory `web`，Build command `npm run build:public`，Build output directory `dist` |
| **Vercel** | 导入仓库，Root Directory `web`，Build Command `npm run build:public`，Output Directory `dist` |

注意：CI 上跑不了 `pipeline\build_data.py` / `extract_ui.py`（它们要读本机的游戏安装），所以 `web\public\data\*.json` 是随仓库提交的；改了数据管线要重新跑一次并提交那些 JSON。

## 开发

```powershell
# 1) 提取官方数据（约 7 秒，产出 web\public\data\*.json 约 9 MB）
python pipeline\build_data.py --out web\public\data

# 2) 数据自检（有硬错误会以退出码 1 结束）
python pipeline\check_data.py

# 3) 提取本机游戏的界面贴图与内容图标（约 14 秒，产出 web\public\assets\ 约 70 MB）
#    需要 UnityPy：python -m pip install UnityPy
#    这步是给立绘卡与内容图标用的；跳过也能跑，只是界面会缺图（立绘卡变文字行、图标变首字）
python pipeline\extract_ui.py

# 4) 可选：重新生成预置构筑（需要 D:\DSH\temp\Wotr-BD- 这份 BD 合集）
python pipeline\import_presets.py

# 5) 起前端
cd web
npm.cmd install          # PowerShell 下必须带 .cmd，npm.ps1 被执行策略拦住
npm.cmd run dev          # http://127.0.0.1:5173
npm.cmd run build        # 产出 web\dist（含 dist\data 与 dist\assets）
```

验证：

```powershell
cd web
node scripts\smoke.mjs                    # 规则引擎冒烟测试
powershell -File scripts\render-check.ps1 # 无头 Chrome 逐个渲染 11 个步骤
```

> **改 `web/src/**` 之前一定要先停掉 vite**：开发服务器在跑时写源码会报
> `Error: ReplaceFileW EIO (Win32 1175)`。停法：
> `(Get-NetTCPConnection -LocalPort 5199 -State Listen).OwningProcess | Stop-Process -Force`，
> 改完再起（`node node_modules\vite\bin\vite.js --port 5199 --strictPort --host 127.0.0.1`）。
> `tsc` 与 `vite build` 用 `node node_modules\typescript\bin\tsc --noEmit`、
> `node node_modules\vite\bin\vite.js build` 直接调，绕开 PowerShell 对 `.ps1` 包装脚本的执行策略限制。
> 无头截图自检：`chrome --headless=new --screenshot=out.png --window-size=1600,1000
> --virtual-time-budget=9000 --user-data-dir=<临时目录> "http://127.0.0.1:5199/#tab=class"`。
