# 游戏内界面复刻规范（Game UI Spec）

来源：`example pictures/` 里 14 张 2560×1440 截图（角色创建全流程，一个「神裔 / 净土裔（天族血脉）/ 习武者」的 1 级先知），
加上从本机游戏素材里实测出来的可提取资源。本文是「网页版尽量贴合游戏 UI」的施工图。

## 1. 整体骨架

游戏的角色创建/升级界面是一本**摊开的羊皮纸书**：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 深色木/金属外框（四角有装饰纹）                                            │
│ ┌ 顶部牌匾步骤条 ──────────────────────────────────────────────────────┐ │
│ │ [新角色] [角色] [肖像] [职业] [种族] [民族] [背景] [属性值] [技能] …  │ │
│ ├────────────┬─────────────────────────────────────┬────────────────┤ │
│ │ 左列表栏    │ 中间详情栏                           │ 右栏（数值/肖像）│ │
│ │ 搜索框 + 行 │ 大号衬线标题                          │ 数值盒子        │ │
│ │ 40×40 图标  │ 正文衬线，机制文字高亮                 │ 本职技能列表    │ │
│ │ 紫色高亮选中│ 图标+名字 网格（可选项）               │ 立绘/3D 娃娃    │ │
│ │ » 表示有下级│ 详情按钮                              │                │ │
│ ├────────────┴─────────────────────────────────────┴────────────────┤ │
│ │ 底部：《 ‹ 返回 │ 下一项 › » ＋ 右侧上下文按钮（详情/职业成长/完成）│ │
│ └──────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

### 顶部步骤条（最关键的特征）

- 每个步骤 = 一块**牌匾**：上面一个 40×40 图标，下面一行中文小标签（角色 / 肖像 / 职业 / 种族 / 民族 / 选择背景 / 属性值 / 技能 / 专长 / …）。
- **未配置**的步骤显示一个「＋」字形；**已配置**的步骤会在它右边长出一小块牌匾显示**所选的值**
  （例：`种族 → 神裔`、`民族 → 净土裔（天族血脉）`、`专长 → 近程射击`、`先知诅咒 → 枯残`、`秘示域 → 先祖`、`启示 → OR 灵魂护盾`、`阵营 → LN`、`姓名 → 1`）。
- 当前步骤牌匾为**紫色高亮**，底部有一个小三角指针对着它。
- 两端有 `‹` `›` 翻页箭头；整条会在窄屏时横向滚动。
- **步骤是动态的**：选定职业后，会按该职业插入它自己的子步骤。先知这一角色实测出现：
  `先知诅咒`、`秘示域`、`启示`、`额外法术`、`法术:等级 1`。其它职业同理（法师的学派/魔宠、巫术、狂暴之力、奥能技艺、盗贼天赋……）。
- 属性值 / 技能 这类步骤在已配置后会缩成一块**小表格**放在牌匾位置（例：`STR 18 DEX 15 CON 13 INT 10 WIS 10 CHA 12`；
  技能则是三行小图标 + 数值 `5 / 7 / 3`）。

### 左列表栏

- 顶部一个圆角搜索框：左放大镜 + 占位「搜索……」，右端一个装饰按钮。
- 每一行 = `40×40 图标` + 名称；**当前选中行是紫色渐变高亮**，左侧还有一撇装饰墨迹。
- 行尾若有 `»`，表示点进去还有下级列表（例：`出身地区 »`、`学者 »`、`元素专攻 »`）—— 与「选择里的选择」是同一件事。
- 部分行右侧有一个**绿色嫰芽/勾**图标（表示推荐或可用）。
- 图标不足时游戏用字母缩写当图标（背景那一列就是 `BMD`=习武者、`BOS`=修士、`BN`=无、`BSS`=学者……）。

### 中间详情栏

- 顶部：`40×40 图标` + 大号衬线标题；下面是「获得能力 / 能力 / 可选项 / 效果」这类**居中偏右的小节标题**。
- 正文用**中文衬线**（宋体感），机制关键词用**紫色或暗红**高亮（例：「体质和魅力属性获得+2种族加值」「达到5级后，你免疫恶心状态」）。
- 「可选项」是**图标 + 名字的两列网格**；选中项再在下面展开大号图标 + 描述 + 一个「详情」按钮。
- 法术详情页的字段顺序固定：`目标` / `施法时间` / `持续时间` / `法术抗力` / `豁免检定` / `难度等级` + 描述。

### 右栏

- 职业页：`强韧 低`、`意志 高`、`反射 低`、`基础攻击加值 中`、`每级生命值 5`、`生命值 8`、`施法属性 魅力`、`施法类型 自发施法`
  —— 每格一个图标 + 标签 + 值，排成 3×3 的盒子；下面「本职技能」是图标 + 名字的列表。
- 最后一步（角色卡）：左栏换成「立绘 + 生命 10/10 + 阵营 + 属性块 + 职业等级徽章」，
  再往下 `攻击`（基础攻击加值 / 近战攻击 / 远程攻击 / 战技 加值·防御 / 先攻权 / 法术抗力）与
  `防御`（防御等级 / 措手不及 / 接触 / 强韧 / 反射 / 意志 + 速度 + 伤害减免 + 能量抗性）两框。

### 职业进度表（职业页/专长页右下）

一行 `等级 1 2 3 … 20` 的圆圈数字，下面是若干行「特性图标」按等级摆放（在会发放该特性的等级上放图标），
最后一行是职业的子选择（`先知诅咒`、`秘示域`……）。这是「逐级规划」最该复刻的视觉。

## 2. 配色与字体

| 用途 | 观察值 |
| --- | --- |
| 羊皮纸底 | 米黄 `#f4edda` ~ `#fbf7ea`，带噪点/水渍/手写淡痕 |
| 深色外框 | 近黑棕 `#1b1410` + 金色细描边 `#b8944a` |
| 高亮/选中 | 深紫 `#5b2a52` → `#7b3a6e` 渐变，白字 |
| 标题/强调 | 暗红棕 `#8b2f2b`、深紫 `#6a2a63` |
| 机制高亮 | 紫 `#7a3d8f`、红 `#a33327` |
| 正文 | 近黑 `#241c14` |
| 中文正文/标题 | 衬线（宋体/明朝体感）。游戏本体没有可直接用的 TTF（`resources.assets` 里只有 Consolas、DOS VGA），
  中文是 TMP 图集 → **网页侧用 Noto Serif SC / 思源宋体**（免费可发布） |
| 拉丁标签 | 装饰性小体大写（如 `STRENGTH`、`ORACLE`），可用 EB Garamond Small Caps 之类替代 |

## 3. 可提取的游戏素材（实测）

| 来源 | 内容 | 结论 |
| --- | --- | --- |
| `Wrath_Data/sharedassets0.assets`（4.8 MB + 92 MB .resS） | **890 个 `Sprite` + 34 张 `Texture2D`**，含 `CharGen_Sprite_Atlas`（2048²）、`Common_Sprite_Atlas`、`HUD`、`Settings`、`LoadingScreen`… | ✅ 名字直接可用：`UI_CharGen_TopMenuCaptionTop`（牌匾条）、`UI_Search_Icon`、`UI_ActionBtn_Active`（按钮）、`UI_RoundIcon_*`、`UI_LocalMap_BorderLine*`… |
| `Wrath_Data/resources.assets` + `sharedassets2.assets` | 网格框、勾选、折叠箭头、噪声/渐变底纹、`Font`×2（ConsolasBold、Perfect DOS VGA 437） | ✅ 零碎控件可用；**没有可用的中文 TTF** |
| `Bundles/blueprint.assets`（19 MB） | **2,232 个 `Sprite` + 2,228 张 `Texture2D`，几乎都是 64×64 RGBA 图标**（实测导出 `Outflank`/`Haste`/`Daze`/`Confusion` 成功） | ✅ 图标本体可导出；名字是内容短名（`PowerAttack`、`RangedFeint`、`DLC5_BleedingCriticalFeature`） |
| `Bundles/*.unit` | 23,570 个文件 / **42.67 GB** | ⚠ 太大，只按需读取 |

**图标对位**：蓝图里是 `"m_Icon": {"guid": "<32hex>", "fileid": 21300000}`（Unity 资源引用，`fileid` 是 Sprite 的固定 pathID）。
实测 `Bundles/<guid>.unit` **不存在**，所以 guid→文件 的对照还没找到，暂时用名字对位：

| 对位键 | 覆盖率（对 features.json 的 10675 条） |
| --- | --- |
| `path` 文件名（`PowerAttackFeature` → 去 `Feature` 等后缀） | 3.4% |
| `nameEn` 去空格（`Power Attack` → `PowerAttack`） | 5.1% |
| 两者串起来试 | 7.6% |
| 法术（`nameEn` 去空格 + 文件名） | **68.1%** |

→ 多数特性图标并不在 `blueprint.assets` 里，需要再找 guid→资源的对照（或改为按需读 `Bundles/*.unit`）。
在有对照之前，网页上的图标策略应是「能对上的用真图标，对不上的用统一底纹 + 首字/字母缩写」——
这恰好也是游戏自己的做法（背景那一列就是字母缩写）。

**道途法术书的数据事实**（改这块前先看）：

| 事实 | 取值 |
| --- | --- |
| 法术池挂在谁身上 | 挂在**法术**上的 `mythicLevels[<道途 id>]`（例如天使 `a5a9fe8f…`），**不是**挂在法术书 id 上 —— 早期按法术书 id 查会得到 0 条 |
| 法术位表的索引 | 所有道途法术书的 `spellsPerDay` 都按**角色等级**（0..20）索引：天使/巫妖从 1 级起（天使 1 级 `[1=1]`），御衡者/灵使/恶魔/诡计大师从 6 级起（灵使 6 级 `[1=2]`） |
| 用哪个属性 | 天使用感知、巫妖用智力，其余（御衡者/灵使/恶魔/诡计大师/金龙）用魅力 |
| 并进职业法术书 | 天使与巫妖（`MERGED_MYTHIC_BOOKS`，`web/src/rules.ts`）；其余是独立法术书 |
| 池子规模（分环） | 巫妖 131、御衡者 103、天使 85、灵使 85、恶魔 63、诡计大师 59、金龙 38（金龙还含 28 条 0 环条目） |


## 6. 素材版权提示

`web/public/assets/**` 全部是从用户本机正版安装里提取的 Owlcat 游戏素材（界面贴图与内容图标）。**自用/本地运行没问题**；若要公开部署，应改用 `skin=plain`，或自行替换素材。该目录已在 `.gitignore` 中排除，不会进仓库。


## 7. 内容图标的对位：实测与上限

蓝图里的图标引用长这样：`"m_Icon": {"guid": "d41189298bcd65d41bad53782de65b27", "fileid": 21300000}`。

* `fileid: 21300000` 是 Unity 里 Sprite 的固定类别号（所有条目都一样），**不是**资源 path_id。
* `guid` 是那个 Sprite 资产的 guid。

**安装里没有可用的 guid → sprite 对照表**（都已实测）：

| 查过的地方 | 结果 |
| --- | --- |
| `Bundles/<guid>.unit` 之类的文件 | 不存在（`Bundles/` 是 23,570 个 `<guid>.<ext>` 扁平文件，`d411*` 一个都没有） |
| `Bundles/blueprint.assets` 的 container | 只有 1 个键，就是它自己的包名 `99d28ed7c8b9caa46a2022f5ce9c0778` |
| `Bundles/icons`（2,341 个 sprite，是**物品**图标）、`Bundles/ui`（1,656 个界面 sprite） | 都没有这个 guid |
| `Bundles/dependencylist.json`（23,566 条） | 键是包名（`fx` / `ui` / `kenabresmap.scenes`…），不是 guid |
| `Bundles/cheatdata.json`（39.8 MB） | 只列蓝图（`Name`/`Guid`/`TypeFullName`/`Path`），不含 Sprite |

所以只能**按名字约定**对位，`pipeline/extract_ui.py` 里的 `candidates()` + `SpriteIndex` 做两轮：

1. 原名（不分大小写）精确匹配；
2. 去掉所有非字母数字再小写后匹配 —— 游戏会把空格写成连字符，例：法术专攻 `Spell Focus` → sprite `Spell-Focus`。

候选名从 `nameEn` / `key` / 文件名 / 路径末几段生成，并剥掉 `Feature`/`Selection`/`Progression`/`Ability`/`Toggle`… 后缀与末尾罗马数字；**不做子串模糊匹配**（实测会把 `Light` 配到 `UnholyBlight`、`Hunter` 配到 `MasterHunter`，属于错配）。

实测覆盖率（`web/public/data/icons.json` 的 `stats`，重跑 `python pipeline\extract_ui.py --prune` 可复现）：

| 类别 | 命中 | 说明 |
| --- | --- | --- |
| 法术 | 498/699 ＝ 71.2% | 玩家最常看的图标基本都有 |
| 特性 | 1886/10675 ＝ 17.7% | 分母里有大量从不露面的内部 buff / DLC 奖励特性 |
| 变体 / 背景 | 1/197、4/55 | 游戏里变体行用 ♦ 圆点、背景行用字母缩写徽记，本来就不是每个都有独立图标 |
| 职业 / 种族 / 神话道途 / 法术书 | 0 | 它们的图标不在 `blueprint.assets` 里（界面里也主要在牌匾条与立绘卡上，本项目按用户要求不做立绘） |

上限参考：`blueprint.assets` 共 2,519 个 sprite，其中还有物品图标与 DLC 奖励 buff；把我们导出的全部实体加起来只能按名对上 924 个。剩余一律回退「统一底纹 + 首字徽记」。
